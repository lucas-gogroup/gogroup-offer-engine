## 1. Falhas de conceito encontradas e como o plano as resolve

1. **Incentivo em % não tem como ser aplicado no checkout Yampi.** O handoff propõe Shopify Function / desconto automático; nada disso roda no Yampi. Sem mecanismo verificado, prometer "10% off" no card e cobrar preço cheio destrói a confiança.
   Resolução POC: escada de incentivo limitada aos degraus que não exigem desconto no checkout: (1) preço cheio, (2) **fechar o gap de benefício** ("leve X e ganhe frete grátis" / "3x sem juros"), (3) preço Pix já existente. Desconto % fica como roadmap dependente de verificação do cupom Yampi (`promocode`) ou de variante precificada. O score continua calculando `price_room` e `expected_margin`, só não publica desconto.

2. **`upsell_purchase` não pode ser disparado pelo tema** (checkout em outro domínio).
   Resolução: reward do bandit = `accept` (Plausible, 15 min). Fechamento de compra = job diário no Data Mart cruzando `properties_data._offer_id` em `gold.shopify_order_items` (paid). Verificado hoje que properties chegam ao pedido.

3. **Nomes de evento colidem**: `upsell_accept` e `upsell_click` já existem na camada do Ápice/gogroup-theme com props diferentes (sem SKU).
   Resolução: eventos do motor passam a ser `offer_impression`, `offer_accept`, `offer_reject`, `offer_checkout` (intenção no clique de checkout com ofertas no carrinho) e `offer_purchase` (só server-side, log interno).

4. **Plausible não existe no `main` dos temas.** O aprendizado depende dele.
   Resolução: portar o conjunto mínimo da camada do Ápice (só adapter Plausible, sem GA4/GTM para não duplicar containers) para os dois temas, no mesmo PR do componente.

5. **App público não lê as bases; cron não tem identidade.** A arquitetura "um Worker faz tudo" não fecha.
   Resolução: dois apps (§2). Aprendizado via Stats API do Plausible com chave (sem proxy). Carga do Data Mart via curador autenticado disparado pelo navegador (cookie presente) e, hoje, também pelo operador (Claude Code via GoRAG). Automação diária = roadmap Airflow (o grupo já roda DAGs com a chave do Plausible).

6. **Timeout de 10 s no Data Mart** inviabiliza co-compra 90 d numa query.
   Resolução: carga em chunks de 1–3 dias, agregada no motor; 30 d bastam para a POC (densidade já alta em 7 d).

7. **Segmento novo/recorrente** só existe quando logado (`customer.orders_count`). Rituária não expõe `customer` no tema.
   Resolução: `segment = returning` se `customer.orders_count > 0`, senão `new`. Aceito como aproximação; declarado no pitch.

8. **Cobertura de custo parcial** (Rituária 162/210 com custo não provisório).
   Resolução: pool de margem só com custo real; demais entram com `confidence = low` e peso de margem reduzido, como já previsto.

## 2. Arquitetura final da POC

```
Tema Shopify (main)                Godeploy                                   Bases
┌──────────────────────┐   POST /recommend   ┌───────────────────────────┐
│ cart drawer / PDP    │────────────────────▶│ offer-api (público)       │
│ snippet offer-engine │◀────────────────────│ SQLite: product_master,   │
│ gogroupAnalytics →   │   oferta + offer_id │ kit_components, inventory,│
│ Plausible adapter    │                     │ cost, affinity, offer_tbl,│
└───────┬──────────────┘   POST /event       │ events_agg, decision_log  │
        │ offer_* events                     │ cron */15: /tasks/plausible│──▶ Plausible Stats API v2
        ▼                                    │ POST /curate (bearer)     │    (chave em secret)
  plausible.aws.gocase.com.br                └────────────▲──────────────┘
                                                          │ push tabelas
                                             ┌────────────┴──────────────┐
                                             │ offer-curator (autenticado)│──▶ proxy PostgREST datamart
                                             │ GET /tasks/daily (browser) │    gold.dim_produto_gobeauty
                                             │ lê proxy com cookie do user│    gold.bridge_kit_componente
                                             └───────────────────────────┘    gold.shopify_inventory_current
                                                          ▲
                                             Claude Code (GoRAG runQuery, chunks) ── co-compra 30 d, custo, prior Yampi
```

**offer-api** (público, slug `offer-api`): `/recommend`, `/event`, `/curate/*` (bearer `CURATE_TOKEN`), `/tasks/plausible` (cron HMAC), `/offers?brand&anchor` (debug/demo), `/log` (decision_log para a demo), CORS allowlist dos domínios das lojas. Score determinístico + Thompson Sampling em SQLite. Zero chamada de modelo em tempo real.

**offer-curator** (autenticado, slug `offer-curator`): lê via proxy as tabelas pequenas (dim, bridge, inventário) e empurra para o offer-api. Disparo manual por URL no navegador (demonstra "motor consumindo das bases na nuvem"). Teste de 15 min no dia: se `gdk_` for aceito pelo proxy, agenda cron externo; se não, fica manual + operador, e Airflow entra no roadmap.

**Aprendizado (Plausible → motor)**: cron a cada 15 min no offer-api chama `POST /api/v2/query` com `dimensions: [event:props:anchor_sku, event:props:offer_sku, event:props:surface, event:props:segment]`, filtros `event:name in (offer_impression, offer_accept)`, janela 30 d, para `site_id` `thebarboursbeauty.com.br` e `rituaria.com.br`; atualiza `events_agg` e re-amostra Beta(accepts+1, impressions−accepts+1) por par × contexto. `/event` continua como feedback imediato para a demo.

**Copy**: templates determinísticos por regra (gap de frete, mesma linha, slow moving). AI Proxy só se a chave `gw-tok` chegar até 16:00; senão fica no roadmap. Não bloqueia.

| Carrinho | Nova estratégia `offer_engine` no bloco `upsell` de `gobeautex-cart-drawer.liquid` (ao lado de `product_list/collection/complementary`). | Add-to-cart da oferta | `/cart/add.js` com `properties: {_offer_id, _offer_sku, recommendation: "1"}` (reaproveita a property que o upsell atual já grava), depois dispara `cart:update` no contrato gobeautex. Botão com classe própria `.offer-engine__atc` (evita hooks de terceiros, ex. Hexagon). |

## 7. Riscos residuais

| Risco | Prob. | Mitigação |
|---|---|---|
| Proxy não aceita `gdk_` → curador só manual | alta | Aceito na POC; Airflow no roadmap; operador carrega hoje |

| Densidade de co-compra baixa em alguns SKUs | média | Afinidade por regra (mesma linha/subcategoria) preenche; âncora por linha |
| Cron Godeploy falha silenciosamente | média | `/tasks/plausible` também acionável por bearer; log em `decision_log`; checar `listCronJobs` |
